# QuantEcon/mystmd — Agent & AI assistant guide

This file provides context for AI coding assistants (GitHub Copilot, Claude Code, Codex, etc.) working in this repository. For the full human-readable contributor guide see [README.md](README.md).

## Repo identity

- **Fork of:** `jupyter-book/mystmd`
- **Remotes:** `origin=https://github.com/QuantEcon/mystmd.git`, `upstream=https://github.com/jupyter-book/mystmd.git`
- **Monorepo** managed with bun + turbo. Build: `bun install && bun run build`. Tests: `bun run test`.
- **Branch protection on `main`** — all changes go through PRs, even single-commit fixes.

## Branch model (critical)

| Branch | Rule |
|--------|------|
| `main` | Mirror of `upstream/main` + `quantecon/` tooling. **Never commit directly.** |
| `feature/<name>` | **Must be branched from `upstream/main`**, not from `main`. This keeps the `quantecon/` folder out of the upstream PR diff. |
| `quantecon` | Throwaway integration build. **Never commit here** — always regenerated by `build.sh`. |

## build.sh — the integration branch tool

```bash
./quantecon/build.sh           # dry run (local only)
./quantecon/build.sh --push    # build and force-push to origin/quantecon
```

- Reads feature branches from `quantecon/features.txt` (strips comments/blanks)
- Resets `quantecon` to `main`, merges each feature branch in order
- Patches `packages/mystmd/package.json` version to append `-qe` (e.g. `1.9.0-qe`)
- Requires a clean working tree (aborts if `git status --porcelain` is non-empty)
- macOS safe: no `mapfile` (bash 3.2 compatible), `BASH_SOURCE[0]:-$0` guard for zsh

**Run after every:** upstream sync, feature branch update, or `features.txt` change.

## Standard workflows

### Add a new feature
1. `git fetch upstream && git checkout -b feature/<name> upstream/main`
2. Develop, commit, `git push origin feature/<name>`
3. Add branch name to `quantecon/features.txt` on `main` (via PR)
4. Open upstream PR: **base `jupyter-book/mystmd:main`**, compare `QuantEcon/mystmd:feature/<name>`
5. `./quantecon/build.sh --push`

### Update a feature branch
```bash
git checkout feature/<name>
# amend/add commits
git push --force-with-lease origin feature/<name>
./quantecon/build.sh --push
```

### Sync main with upstream
```bash
git fetch upstream
git checkout main && git merge upstream/main && git push origin main
./quantecon/build.sh --push
```
Or use the GitHub "Sync fork" button, then pull locally and rebuild.

### When upstream merges a feature
1. Sync `main` with upstream
2. Remove branch from `quantecon/features.txt` (via PR)
3. `git branch -D feature/<name> && git push origin --delete feature/<name>`
4. `./quantecon/build.sh --push`

### Fix conflicts
Conflicts are **always fixed on the feature branch**, never on `quantecon`.

```bash
git checkout feature/<name>
git rebase upstream/main      # or rebase onto the conflicting feature branch
git push --force-with-lease origin feature/<name>
./quantecon/build.sh --push
```

## Installing the quantecon build (GitHub Actions)

```yaml
- uses: actions/setup-node@v4
  with: { node-version: '20' }
- uses: oven-sh/setup-bun@v2
- name: Install mystmd (QuantEcon fork)
  run: |
    git clone --branch quantecon --depth 1 \
      https://github.com/QuantEcon/mystmd.git /tmp/qe-mystmd
    cd /tmp/qe-mystmd && bun install && bun run build
    npm install -g /tmp/qe-mystmd/packages/mystmd
- run: myst --version   # should print e.g. 1.9.0-qe
```

A simpler npm-based install (Option B) is tracked in [issue #19](https://github.com/QuantEcon/mystmd/issues/19).
